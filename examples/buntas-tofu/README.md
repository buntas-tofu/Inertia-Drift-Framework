# README Standard

Every project README must contain the following sections once populated.
Sections may be reordered but not omitted. If a section is genuinely
not applicable, replace its content with a one-line explanation of why.

## What this project is

One sentence. What it does, who it is for, and why it exists.

## How to run it

The minimal commands. If there is nothing to run, say so plainly.

## How it is governed

Which DMF artifacts are in effect (GLOBAL, LOCAL, the manifest) and where
they live.

## Status

The status line: what this artifact is, what it is not, and who may act
on it. Example: "Testbed observation, not an agency finding, not policy."
